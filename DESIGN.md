# Design system

Rex Linux draws calm, dark chrome around terminals that the server owns. Chrome palettes are token sets defined in `src/app/theme.rs`, which is the source of truth, and chosen at runtime (Settings → Interface → Theme): Midnight, the default, Rosé Pine, Rosé Pine Moon and Gruvbox Dark. Their tokens are listed below (update both together). Each palette pairs with a built-in terminal theme whose background equals the chrome's ground, so a single pane reads as one surface with the toolbar. Palettes are dark only and change colours only; fills, borders, motion and layout are shared.

## Principles

- **The terminal is the content.** Chrome frames it and stays out of the way. Terminal text, colours, cursor, block order and split nesting come from the server and are never recoloured; a terminal theme the client declares reaches the terminal through the server (Rex's `set_theme`). Tiled tabs use the server's ratios. A tab's local scrolling view may instead give its top-level horizontal columns client-owned widths; splits inside each column keep the server's ratios. The one colour exception: the server's default terminal background is drawn in the palette's `CARD` colour (or the background of the theme this client declares), the same as the ground, so a single pane and the toolbar read as one surface. It is substituted only when both are dark or both are light, so a light default under another client's light theme, or under a server that ignored `set_theme`, keeps its own colour and the default text stays legible. Explicit background colours and inverse video's block are preserved; the substitution is by colour value, so an explicit background equal to the default is filled too.
- **Cells don't animate.** Popups spring open from their anchor and highlights and the sidebar slide. Terminal cells, colours and cursor never interpolate or crossfade. Cards spring to server layout changes and to a focused column's automatic pan as rigid surfaces; direct wheel panning is immediate.
- **One working row.** Session identity, tabs, commands and the window's own controls share a single toolbar. Navigation (hosts → sessions) opens on demand, with an optional sidebar. The Sidebar tab position is an option that moves tabs out of the toolbar into the sidebar while the sidebar is open and lists sessions; closed, or while it shows Activity, the toolbar shows them again.
- **Quiet when healthy.** A connected host, a live pane and the active tab carry no status dots or "Connected" labels; names and host icons are enough. Words appear only for trouble ("Offline", "Reconnecting", "input paused"), in `WARNING`, next to the action that fixes it. The exception is program activity: a tab whose programs finished while the user was away says "Done" in `ACCENT` until it is seen, a terminal bell that rang out of sight says "Bell" in `WARNING` until its tab is seen, and a tab whose program reports its progress (OSC 9;4) draws it as a 2 pt bar along the pill's bottom edge in `ACCENT`, with no word, until the program clears it or leaves the foreground; a tab whose program is working (OSC 7501 Working, or a running OSC 9;4 report) shows three 4 pt `ACCENT` dots after its label, their opacity rising in turn on a 1.2 s loop (still under reduced motion), wherever no word has the slot; a paused report says "Paused" in `WARNING`, with its percentage when it gave one, and a failed one "Error" in `DANGER`, each over a bar in the same colour.
- **Distinct states.** The current session, the keyboard-selected row, a captured pane target and live terminal focus each have a different cue. Keyboard selection is never fill alone.
- **Name the target.** Creation actions name their host; destructive confirmations name the pane, tab and host and default to **Keep running**; closing the app leaves server programs running.

The paired terminal themes are Midnight (its navy behind Rex's default text), Rosé Pine and Rosé Pine Moon as their Ghostty themes draw them, and Gruvbox Dark's background, text, cursor and 16-colour palette. In every palette `MUTED` on `CARD` and `INK` on `POPOVER` meet WCAG AA (4.5:1); `WARNING` and `DANGER` are at least 3:1 on both surfaces (Gruvbox Dark's red is the lowest, 4.3:1 on its ground and 3.4:1 on popovers) and always carry a word. Switching palettes is instant: colours change in one frame, with no crossfade.

Interaction fills are translucent white over the surface: hover 7%, pressed 11%; borders 6–20% white (focus uses `ACCENT`). Trouble states always carry a word, never colour alone; healthy states show nothing. There is no light chrome palette.

## Typography

Chrome uses Inter (bundled with the kit) in 10–13 pt steps, weights about 450 (body), 560 (medium), 620 (strong); group labels are 10.5 pt small capitals with 0.6 tracking. The terminal family, ordered fallback families and size (8–48 px) are saved locally, and `--font`, repeated `--font-fallback` and `--font-size` override them for one launch; the default is JetBrainsMono Nerd Font 15. Missing glyphs come from the named fallbacks in order, then fontconfig's sorted fallbacks for the terminal family, then bundled IBM Plex Mono, then the system's script and symbol fallbacks; an unavailable primary is replaced by IBM Plex Mono. Family changes apply after reopening the client. Cell width follows the primary font's advance; ligatures and kerning are off so the grid stays exact. Names keep their case and ellipsize when space is bounded, with tooltips for the full text. Server windows are called **tabs**.

## Layout and shape

- **Toolbar:** 52 pt chip bar. Controls sit on glassy chips (10 pt radius, 5.5% white fill, gradient hairline border). Tab pills are 96–240 pt wide with no close button: a tab closes from its right-click menu, a middle-click or `Ctrl Shift W`. Commands (⌘), New tab (+) and Settings (sliders) sit at the right end with Close, all as bare 15 pt icons on a 36 pt pitch with no fill at rest; hovering shows the same 30 pt round fill on each (9% white, `DANGER` at 22% for Close). A 1×16 pt hairline divides the app's buttons from Close. There are no minimize or maximize buttons: tiling window managers often ignore them. A pill shows its focused pane's program icon, its label, and then a word for program activity: "Needs approval", "Question", "Needs sign-in" or "Needs input" in `WARNING`, "Error" in `DANGER`, unseen "Done" in `ACCENT`; idle tabs show nothing and working tabs show the working dots instead of a word (with a working program's progress as the bar under the label). The sidebar's tab rows show the same dots. A tab still called "Shell", the name new tabs get, shows its focused pane's terminal title instead while the program that set it is in the foreground; a tab the user named keeps its name. The label truncates before the word or dots do; the program's message is the word's tooltip. The empty space moves the window; edges and corners resize it.
- **Terminal search:** `Ctrl Shift F` opens a 280×34 pt field pinned 6 pt inside the terminal's top-right corner, on the popover colour with a 1 pt hairline and an 8 pt radius. It shows `esc` while empty, then the selected match's place among all matches (`2/5`) or "No matches". While it holds the keyboard, the terminal's cursor is the hollow outline of a pane without it.
- **Single pane:** a tab with one pane, not zoomed, draws it edge to edge under the toolbar with no card, header, border or margin. Its exception strip floats at the pane's top-right corner.
- **Pane cards:** splits, and a zoomed pane, are server-defined placements as rounded cards (12 pt radius) with a 30 pt header (pane name, its program's activity word, and when needed its exception strip), 8 pt gutters and 10 pt outer margin on the ground; their border separates them from the same-coloured ground. Terminal text has 8 px padding inside its card; a terminal background other than `CARD` fills the card's body inside its border, below the header, with the card's bottom corners. Divider drags preview immediately and send a ratio clamped to 0.1–0.9. The header's word is the tab's word for that pane alone (trouble and progress; Done and Bell stay with the tab), follows each state's Tabs channel in Settings → Notifications, carries the program's message as its tooltip, and stays whole while the name truncates. A pane whose label is still its terminal's default (`shell`, the last word of its flavor) shows its program's terminal title while that program is in the foreground, as a "Shell" tab does; a renamed pane keeps its name, and a pane renamed to exactly `shell` counts as unrenamed. The title is display only: the server label is never changed, and Rename starts from it.
- **Scrolling tabs:** a tab set to **Scrolling** (its own choice, or the Interface default) draws the server's top-level side-by-side parts as columns in server order, ignoring the server's ratios between them: half the pane area wide by default, 0.1–1 window after adjustment, saved per host, session, window and column. Splits inside a column keep the server's ratios, and a lone column fills the area. Columns past either edge are clipped there; horizontal wheel or trackpad scroll (and the plain wheel over gutters and headers) pans the strip, and focus moving to another pane pans just far enough to show its whole column, with the card spring. Dragging a full-height column boundary resizes only the column on its left; the columns on its right keep their widths and move with it. The layout, widths and strip position are local to this client and never sent to the server.
- **Sidebar:** optional; it opens at launch as it was left, at its saved width. Default 236 pt wide (200–360 pt, drag the edge to resize, double-click to reset). Host rows are 28 pt, session rows 32 pt, groups separated by 12 pt. With the Sidebar tab position, a session's row becomes a 24 pt muted label and its tabs follow as 32 pt rows indented 12 pt, each with the toolbar pill's icon, label and activity word; the active tab gets the pill's fill and hairline. A session row (and that 24 pt label) also shows the session's activity word in 10.5 pt and, when two or more of its panes need you, their count in `WARNING`; a session whose program reports progress draws the tab pill's bar along the row's bottom edge, inset 10 pt. A two-segment Sessions / Activity switch (26 pt segments, the active one on the tab pill's fill and hairline) chooses what the sidebar lists. Below it, Sessions mode has a 32 pt "Find a session" chip that opens the switcher (⌃K); Activity mode lists panes rather than sessions, so it has none. The Activity segment carries the unread count after its label, 10.5 pt medium, in `WARNING` while any counted pane needs you or failed and in `ACCENT` when all are unseen Done, and nothing at zero; the same count goes to the desktop's launcher badge. Activity mode lists one 44 pt row per pane across hosts: a 15 pt program icon, the pane name (12.5 pt) with its activity word (10.5 pt, in its tone) on the first line and an 11 pt muted detail on the second. The detail and the name truncate; the word never does. Reported subtasks follow as 24 pt rows indented 12 pt, plus 12 pt per level. Groups have a 26 pt uppercase label and are separated by 12 pt. A 40 pt bar at the bottom holds Priority / Session segments and an Idle toggle. With nothing to show the list says "No programs are reporting activity." in muted text.
- **Popovers:** session/host menus anchor to the identity; pane and tab menus to the pointer (right-click), and pane menus also to the toolbar; the command menu is centered near the top. Popovers are compact: the switcher 340 pt wide, Commands 460, pane menus 260; 28 pt rows (30 in Commands), 26 pt group headers, a 34 pt search field, 5 pt padding and a 12 pt radius. Popovers clamp to the viewport; long lists scroll with directional hints that count hidden rows. A popover never opens another popover from its rows: the switcher's session rows show the session's activity word (with the count when two or more panes need you) as their detail, or for a session whose only activity is working progress (which the sidebar draws as a bar) its percentage or "Working", since the switcher has no bar, after the host unless the list is sessions only; the highlighted session row trades its detail for pencil and × buttons, and renaming turns the row itself into a field (accent outline) until Enter or Esc.
- **Dialogs** (forms, confirmation) are centered over a dark scrim and sized to their content within the viewport. **Settings** is a larger dialog (760×520, clamped to the viewport) with a 190 pt section list on the left and the section's rows on the right; each row names the setting, explains it in one muted line and puts its control on the right. Notifications is a channels × states table instead of a row per switch: a 10.5 pt small-caps caption row (Tabs, Desktop, Count, Sound), then one row per state (Needs you, Fails, Finishes, Works) and Messages from programs, each with its name and muted explanation on the left and a 64 pt column per channel holding a 16 pt kit checkbox; a channel that doesn't apply to the row shows a muted dash, as does Sound while the row's Desktop is off (its tooltip says why, and the saved choice returns with Desktop). Forms, confirmations and the chrome and terminal theme lists opened from Settings return to it.
- **Shortcuts:** Settings lists the active host’s effective bindings (local defaults plus overrides while offline), in registry categories and action order, then by arguments, retaining try order within an action/argument group. Keep 190 pt keycap columns and 12.5 pt labels; sequence chords stack with a muted “then”. Linux defaults omit the source line; other sources use 10.5 pt muted text. Matching numpad defaults fold into an “also numpad” hint; the four default pane-focus bindings share one “Ctrl Alt Arrows” row. Scroll labels name direction and line count. Problems remain below the bindings and both file paths are selectable. A pending sequence adds one quiet toolbar chip (`Ctrl B …`, at most 170 pt with a full tooltip); Escape cancels. No timeout, pulsing or terminal animation.
- **Radii:** kit small 8, medium 10; chips 10; cards and popovers 12.
- **Icons:** authored strokes on a 20×20 view box, 1.5 stroke, round caps and joins, `currentColor`. Hosts show their kind (a monitor for this machine's Unix socket, a server for a remote endpoint) in the identity chip, sidebar headers and switcher groups; tabs carry their program's icon at 15 pt (Claude Code, as `claude` or `claude-code`; Codex, OpenCode, Pi, whose mark OMP shares; Vim, Git, Cargo, SSH), or `>_` for shells and anything else. Pi and OpenCode use solid marks after their own logos, since outlines of them are unrecognisable at that size; the Commands button is ⌘. Magnifying glasses mark search fields only.
- **Elevation:** the working canvas is flat. Popovers and dialogs get a frosted fill, a lit gradient rim and a deep soft shadow.
- **Interface zoom:** 70–150% in 10% steps. Zoom above 100% is limited to preserve a 640×480 layout floor where the viewport allows; terminal font size is independent.

## Interaction

- Workspace defaults are listed in the README; every binding is removable or replaceable. The active host’s effective map drives dispatch, Settings and Commands; unbound keys reach the terminal through `client.key`. Only popup editing/navigation and Escape cancelling a sequence remain reserved. Commands details use the highest effective binding for their action and args; unbound actions have no keyboard hint, while mouse Back/Forward retain literal pointer hints. Ctrl Tab and Ctrl Shift Tab traverse connected hosts, sessions and cached tabs in sidebar order, wrapping; an uncached session is one stop. Cross-session cycling settles for 150 ms before attachment, without animating terminal content. Mouse Back and Forward revisit window-local history and never reach terminal mouse reporting or navigate behind a panel. Commands exposes the same named navigation actions; Ctrl PageUp and PageDown remain server-controlled within the current session.
- SSH setup is separate from attachment: a missing default server offers **Start personal server…**, then a dialog names the host, full endpoint, exact command and effects. **Not now** is the default; only **Start personal server** authorizes a one-time attempt. Busy setup disables repeated starts, errors remain in the dialog, and closing a busy dialog does not claim to cancel the remote start. No automatic future start or installer prompt approval is implied.
- Opening a form or search focuses its first field; close confirmation focuses **Keep running**. Tab and Shift-Tab cycle fields and actions in panels; Enter and Space activate; Escape backs out and restores the previously focused pane. Tab, Space, Return, Escape and Menu never move focus away from the terminal unless a panel is open.
- Right-click captures the specific pane under the pointer; its menu names tab and pane and keeps a target outline through rename and close. A target that disappears dismisses the menu with a notice instead of retargeting.
- Size ownership is automatic: the active window owns terminal size and typing claims it. A non-owner or reconnecting terminal shows an exception strip with **Take control** or **Retry**, and never sends a resize.
- A transport failure marks affected panes input-paused, keeps their output, and never queues or replays input. Notices are toasts: errors are sticky, information leaves after about 6 seconds, and at most three notices are retained.
- Remote control is a per-host switch in Settings → Remote Hosts, off by default, with a Commands toggle for the host on screen. The client label is editable there too. No healthy-state badge: each performed request gets one six-second notice naming host, requester and action. Off explains itself once per host per launch; other refusals are quiet. Requests never raise the window or open a dialog.
- Focus cues: the focused terminal draws the cursor shape its program asked for (a filled block unless it chose a bar or underline), other panes a hollow outline block, and the focused pane has an accent outline when no panel is open. Cursor blink requests draw steadily, like the rest of terminal content.
- Links open only on Ctrl+click (press and release on the same link), never on a plain click, so selecting text and clicking into programs stay unchanged. Holding Ctrl over a link underlines it in its own text colour, shows the hand pointer and gives it a tooltip with its target URL (never its displayed text).
- A horizontal wheel or trackpad gesture over a scrolling tab pans its strip immediately; a precise gesture springs to the nearest column edge when it ends. Focus movement follows the Interface policy: reveal only, center when the previous and new columns cannot fit together, or always center. **Center column** centers explicitly. `Ctrl Shift S` cycles 1/3, 1/2 and 2/3 widths; `Ctrl Shift M` maximizes and restores. Split right creates a new top-level column after the focused whole column. Single-pane columns can swap left or right; a pane can move vertically into an adjacent column or horizontally out of its multi-pane column. These actions use server `swap_blocks` and `move_block`, keep focus on the moved block and migrate local widths after the server confirms the topology. Multi-pane whole-column movement stays unavailable until the server can move a split subtree atomically. Vertical wheel over terminal content remains terminal scrollback or program mouse input.

## Do and don't

- Do keep the toolbar single-row and the terminal canvas dominant.
- Do keep chrome tokens in `theme.rs` rather than hard-coding colours in views.
- Do derive overflow cues and hidden-row counts from measured content.
- Don't recolour terminal output to match the chrome, or animate terminal content.
- Don't let selecting, copying or navigating claim size ownership.
- Don't add status dots (the working dots are program activity, not health), "Connected" labels, terminal size readouts or keyboard-hint footers.
- Don't show illustrative sessions, layouts or captures as shipped runtime state.
