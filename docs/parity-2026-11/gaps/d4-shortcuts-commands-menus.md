# D4. Shortcuts, command palette, menu bar and context menus: Rex Linux 0.6.0 versus Rex Beta 0.1.0 (macOS)

Analyst: parity domain 4. Sources: `docs/parity-2026-11/beta/b05, b08, b09`, `rune/r02, r03`, `code/c02, c03`, the screenshots (beta 038-051, 072-095, 125-131; Linux 06, 25-29, 31-32, 35, 38, 41-49) and the source and vendored SDK. Screenshot numbers: **B###** = Rex Beta, **L##** = Rex Linux. Sizes in the Linux column are points from the code (c02). Correction (verification pass): the Linux screenshots are native 2560x1410 captures at about 1.28 device scale, so a measurement on the 2000-px-wide view equals points (Commands panel measures about 466 pt, code says 460); the claim here that r02/r03 values run "about half" of the code values comes from reading downscaled thumbnails and must not be reused. Source paths: `keymap.rs` in this document means `src/keymap.rs` (defaults at lines 370-414), the registry is `src/app/actions.rs`.

## 1. Summary

Linux has a good *engine* here and a thin *surface*. The key pipeline is stricter and more capable than the beta's as documented: three keymap layers (Linux defaults, host Rex config, client `shortcuts.json`), multi-key sequences with a pending-sequence chip, sequence-safe release forwarding, remote-consent gating, physical-key matching for non-US layouts, and a host-grouped session switcher with inline rename and close that is ahead of the beta's. The Commands list (25 rows, contextual host and pane groups, sessions and tabs when filtering) is also broader than the 15 rows the beta shows.

The gaps are in what the user can *see and change*, and in action coverage. (1) Settings > Shortcuts is a read-only reference of 28 bindings; the beta lists all 118 actions (56 bound, 49 unbound, 11 parameterised/not recordable), filters by name or key, records bindings inline, shows conflicts in priority order and has a Configuration menu (copy path, copy as Lua, reset all). Linux has no recorder, no filter, no way to see an unbound action, and by policy never writes `shortcuts.json`. (2) The registry has 32 actions against the beta's roughly 100 distinct ones. Missing, though the server API already supports them (`session.move_window`, `session.float_block`, `session.move_block`, `session.swap_blocks`, `session.set_layer_state`, `session.focus_next_pane`, `terminal.clear`/`reset`, `terminal.list_dir`, `new_split` before-side): tab reorder, move/swap/float/minimize panes, focus next/previous pane, split left/up/best fit, clear/reset terminal, select all, go to directory, insert path, next/previous session, close other tabs/panes, go to tab defaults. (3) The pane right-click menu has no Copy, Paste, Select all, Reset terminal or four-way split, and the tab menu has no Mute or Move. (4) There is no menu bar (correct for a tiling-WM Linux app: Commands is the equivalent, but it does not yet reach every beta menu item), no activity popover, no Go to Directory/Insert Path overlays, no Rex Help item, no tray.

Of 152 rows in the matrix (after the verification pass; 149 originally): 24 parity, 54 partial, 51 missing, 7 linux-ahead, 5 linux-only, 11 not-applicable (macOS idioms, mostly). Of the 51 missing rows, 36 need no server or Rune work, 10 hit a product rule, 3 need Rune work and 2 are unknown; none needs new server API once checked against vendor/rexrs (the original count of 3 was wrong: onboarding blocks and key modes are in the API, and no pairing method exists so Pair Device is unknown). Rows blocked on a product rule are the recorder (PRODUCT.md: Settings explains sources without writing the override file), the palette footer (DESIGN.md forbids keyboard-hint footers), toolbar placement and light chrome. Multiple windows is not a documented product rule (see B01).

Platform translation used throughout: Cmd chords cannot be copied (`cmd` in Linux config means Super, and plain Ctrl belongs to programs), so parity means the *action* exists with a sensible Ctrl+Shift / Ctrl+Alt default. A menu bar is replaced by the Commands list plus context menus; Services, Writing Tools, AutoFill, Dictation, Window tiling, Stage Manager and Apple feedback have no Linux counterpart.

## 4b. Where Linux is deliberately different

- No global menu bar: Commands plus context menus are the Linux equivalent; adding a menu bar would break "one toolbar" and Rune has no native Linux menu bar (its `popup_menu` is native on macOS only; verify before relying on it).
- Terminal dimming while searching (B126) conflicts with "the client never recolours terminal output".
- Footer hint bar in the palette conflicts with DESIGN.md "no keyboard-hint footers".
- Cmd-based macOS defaults cannot be copied: plain Ctrl reaches programs, `cmd` means Super. Use Ctrl+Shift for app actions, Ctrl+Alt for pane geometry.
- No tab/pane auto-creation: every new action that creates (Move pane to new tab, New floating pane, Go to Directory) must remain explicit user actions.
