# d6: Developer settings, diagnostics, RexSync, network, GPU, updates, About

Parity analyst report for Rex Linux 0.6.0 (Rust on Rune, commit ad196ff) against Rex Beta 0.1.0 (1932) for macOS. Domain: Settings > Developer, the Diagnostics window and its inspector, RexSync, Network, GPU, updates and About.

Sources read: beta specs b07, b10, b11, b01 plus b05/b08/b09 where they touch updates, Diagnostics shortcuts and the status item; Linux spec r01; code inventory c04. Screenshots opened side by side: beta 004, 055, 102, 104, 108, 114 and Linux 07, 08. Beta numbers are `rex-beta-ui-2026-11-10/screenshots/NNN`, Linux numbers are `rex-rune-2026-11-11/screenshots/NN`. Linux code was grepped to confirm each "missing".

## 1. Summary

In this domain Linux has almost no developer or diagnostics surface, and a stronger update story than the beta. The beta has a Developer settings page (developer mode, update channel, Rex helper provenance, local API URL, web origins, six experimental switches) and a separate six-pane Diagnostics window (Rex Binary, Rex Server, Rex API console, RexSync state dump, Network recorder, GPU usage) with a per-pane inspector. Linux has none of that: Settings has eight sections (`src/app/panel.rs:181-201`), there is no Diagnostics, the only diagnostics are `REX_FRAME_STATS` on stderr (`src/app/stats.rs`) and the About page. Linux is ahead on updates: signed Minisign metadata with anti-rollback, install-channel detection with a copyable upgrade command, an update toast, a visible "Check now" result and a CLI mode, while the beta's own "Check for Updates…" shows no result at all (COVERAGE.md). About is close on data but thin on identity: no icon, no connected server version, no Copy Debug Info.

The cheapest high-value gap is server identity: `server.version` and `server.status` exist in the vendored API (`vendor/rexrs/codegen/help.json`); `server.version` is never called and `server.status` is called only to list listeners in Add host discovery and SSH setup. Together they supply every row of the beta's Rex Server inspector except executable path and log file. Most of Diagnostics is client-side work with no server dependency (host state, API console, event log, Rex CLI provenance, network recorder). Items blocked by product rules: the Developer-page update toggles (the client never installs itself) and cursor shaders (terminal content never animates). Stop Server is a product decision, not a rule (only attachment and reconnect are barred from stopping a server; server.stop works over the local socket only). Web Client Origins and live server logs need a server API: help.json has no origins or log method.

Counts of the 66 matrix rows by status: linux-only 7, missing 38, not-applicable 7, parity 2, partial 12.

Platform mapping used throughout: macOS menu bar becomes Commands (Ctrl Shift P) plus the toolbar Settings icon; Shift-Cmd-, becomes Ctrl Shift , (free in the default keymap); traffic lights are not drawn on Linux (DESIGN: no minimize or maximize buttons); the menu-bar extra becomes a StatusNotifierItem tray (Rune ships `vendor/rune/crates/rune/src/tray.rs`, GNOME needs an extension); Services, Quick Look, Stage Manager and "Included with Rex.app" have no Linux meaning.
