# D1: Workspace chrome parity (Rex Linux 0.6.0 vs Rex Beta 0.1.0 for macOS)

Domain: window, toolbar, tabs, panes and pane headers, sessions and the sidebar, status indicators (there is no status bar in either product), activity, the menus and overlays that act on them. Settings pages are covered by other domains and are referenced only where they control chrome.

Sources: `docs/parity-2026-11/beta/b01, b02, b05, b06, b08, b09`, `rune/r01, r03`, `code/c02`, the screenshots (beta `B001`..`B137`, Linux `L00`..`L49`, written below with those prefixes), the beta accessibility trees (`rex-beta-ui-2026-11-10/evidence/091-activity-popover.json` gives the toolbar and pane-header bounds in points), `DESIGN.md`, `PRODUCT.md`, `AGENTS.md`, and `vendor/rexrs` for what the server offers.

## 1. Summary

Rex Linux already matches the beta on the core workspace loop: one toolbar row with a session chip, tab pills and Commands/New tab buttons, a session switcher with filter-or-create, a Commands palette, split/zoom/close, rename and close dialogs that name their target, terminal search, and program activity as words and progress on tabs. In several places it is ahead: a host-grouped session sidebar, multi-host switching, session reordering, reconnect strips and named-target confirmations. The gaps are in direct manipulation and in the layout vocabulary the beta exposes. There are no pane header buttons (split, float, zoom, close), no pane header or toolbar visibility modes, no Left/Right toolbar layout, no tab reorder or mute, no Activity popover, no floating panes, no pane move or balance, no Split Left/Up/Best Fit, no terminal context menu with Copy/Paste/Reset, no Go to Directory or Insert Path, and a thinner find bar. Most of these are client-only work: `vendor/rexrs` already exposes `session.move_window`, `session.float_block`, `session.new_layer`, `session.set_layer_state`, `session.swap_blocks`, `session.move_block`, `session.focus_next_pane`, `session.new_split` with `side:"before"`, and `com.superlogical.terminal.list_dir`, `.pwd`, `.reset` and `.clear`; none of them is called from `src/`. Only multi-window (Rune), full screen (Rune; vendor/rune has no setter), a tray item (Rune), trackpad gestures and an app-global show/hide hotkey need Rune work, and three beta behaviours collide with Linux product rules (light chrome, a visible tab close button, dimming inactive terminal content).

On visual quality the beta is denser and more tactile: a 46 pt toolbar with 32 pt capsule tabs, a card-on-chrome pane with a header that always has action buttons, a saturated accent selection pill in every list, separators in every menu, and a 330 pt palette. Linux is calmer and flatter by design (DESIGN.md). Its main quality problems are a weak list-selection cue (grey-blue fill), flat menus with no separators or destructive styling, a ragged shortcut/chevron column, hard-coded tooltip shortcuts, a find bar that covers the prompt and has no controls, and sidebar count badges that say "1" on every row.

**Measurement caveat for the Linux specs.** `r01` and `r03` assume the Linux captures are 2x and halve all pixel sizes. They are 1x captures (2560x1410 at Interface zoom 130%), so the true size at 100% zoom is original px / 1.3. Check: the toolbar is 52 pt in `theme.rs:198`, 52 x 1.3 = 67.6 px, and the screenshot toolbar measures about 67 px; the sidebar is 236 pt x 1.3 = 307 px and measures about 313 px. Use code constants, not the halved numbers in r01/r03. Beta numbers are real points (1x display, 100%).

Counts below come from the matrix after verification and the completeness review: 118 rows, 39 missing, 36 partial, 17 parity, 6 linux-ahead, 13 linux-only, 7 not-applicable (the first draft had 109 rows: 36 / 35 / 16 / 9 / 6 / 7).

## 4. UI quality deltas

Numbers compare at equal zoom (Linux at 100%). Screenshots: beta `B`, Linux `L`. Fixes name the Rune view or token file. Several fixes touch DESIGN.md decisions; those are flagged "needs a design call".

1. **List selection is too quiet.** The beta fills the selected palette, switcher and activity row with a saturated accent pill and white text (B089, B090, B091). Linux selects with `#222A38` or `#363F4C` grey-blue (L41, L43, L38), barely distinct from hover; DESIGN.md already requires that keyboard selection is never fill alone. Fix: add a `SELECTION` token (ACCENT at about 28% plus ACCENT 1 pt outline, text stays INK) in `theme.rs`, use it for `selected` rows in `popups.rs` `list_popup` (around `popups.rs:237`), and keep the target ring for context. Needs a design call on whether Linux wants a solid pill like the beta.
2. **Menus have no structure.** Beta menus separate groups (B092: rename | move | close; B094: clipboard | split/zoom | close/reset | system) and palette lists group by task. Linux context menus are one flat list (L31, L32, L35, L38) and Commands has 19 unsubgrouped Workspace rows (L41). Fix: let `list_popup` render a separator row, then insert separators in `panel.rs` (`pane_menu` list near `panel.rs:716`, tab menu `panel.rs:563`, session menu `panel.rs:367`, host menu `panel.rs:420`) and split Commands into Session / Tab / Pane / App groups in `panel.rs:514-859`.
3. **Destructive items look like every other item.** `Close pane...`, `Close tab...`, `Close session...`, `Remove host...` are plain text in menus and Commands (L31, L32, L35, L38, L41); only the confirmation is red. Fix: a `danger: bool` on the popup row spec, text in DANGER at 90%, rendered after a separator (`popups.rs`, `panel.rs`).
4. **Shortcut and chevron columns are ragged.** Hints end at different x depending on whether a `›` follows (L38 hints stop at x 459, chevrons at 466; L41 `Ctrl K ›` and `Ctrl ,` sit left of the others). The beta aligns hints and reserves the chevron column (B090). Fix: always reserve a 12 pt chevron column in `list_popup` rows (`popups.rs:82-439`).
5. **Shortcut notation is inconsistent and plain.** Linux writes `Ctrl Shift D` in menus, `^K` in the sidebar search (L30), and `Ctrl ,` for Settings; the beta uses compact glyph strings (`⇧⌘N`). Fix: one formatter in `widgets.rs` producing keycap chips (`Ctrl`+`Shift`+`D` as 10.5 pt chips, `MUTED`) used by menus, Commands, switcher, tooltips and the sidebar hint; replace `^K` with the effective binding.
6. **Tooltips lie after a rebind.** `toolbar.rs:292-359` and `sidebar.rs:440` hard-code `Ctrl Shift B`, `Ctrl K`, `Ctrl Shift P`, `Ctrl Shift T`, `Ctrl ,`. Fix: build the `help` text from `s.effective_keymap()` the way Commands details already do (`panel.rs:861-873`).
7. **No pane header action buttons.** The beta pane header (B001) carries Split Right, Split Down, Float, Zoom and Close at 22 pt, dim when unavailable. Linux has a 30 pt text-only header, and not at all for a single pane (L00, L38), so mouse users have no visible way to split or close.
