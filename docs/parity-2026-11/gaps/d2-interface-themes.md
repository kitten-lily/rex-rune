# D2: Settings shell, Interface settings and Themes

Parity analysis of Rex Linux 0.6.0 (Rune) against Rex Beta 0.1.0 (macOS). Domain: the Settings shell, Settings > Interface (and its Tabs and Panes sub-pages), the Themes library, the theme editor, the extended palette, the theme switcher, colour scheme and app icon, plus the View > Customize View menu that mirrors them.

Sources: `docs/parity-2026-11/beta/b01, b02, b03, b05, b08`, `rune/r01`, `code/c01`; screenshots beta 005-021, 072-088, 129 and Linux 00, 01, 02, 09, 11, 13, 14 (opened and compared); `src/app/settings_view.rs`, `panel.rs`, `theme.rs`, `workspace.rs`, `terminal_theme.rs`, `vendor/rexrs` (`SetTheme`, `FocusBlock`; no balance call). Beta colours are macOS dark-mode samples; "Linux" colours are the Rex Linux tokens.

## 1. Summary

Linux has a working but thin Interface page: one chrome theme (four dark palettes), a UI zoom stepper, pane density, a session sidebar switch, tab position and notice position, all as flat label-plus-helper rows in a 760x520 modal. It has no Themes page, no light chrome, no system light/dark following, no theme editor, no extended palette, no Settings search or history, and no Tabs or Panes sub-pages. Its terminal theme story is different in kind: the client declares a theme to the server through `terminal.set_theme` (Follow server, Rex default, Follow chrome, 4 built-ins, any installed Ghostty theme, about 600 with Ghostty present: 607 files in `/usr/share/ghostty/themes` on the capture machine), which is richer than the beta's 41 themes (Merino Light, Merino Dark and 39 built-ins) but has no previews, no light/dark pairing, no import button and no way to create a theme. A searchable switcher already exists, but only inside Settings > Terminal and it replaces the Settings panel, with no Commands entry.

The largest feature gaps are (1) the Themes model: light and dark selections, a thumbnail library, a theme editor and the extended palette; (2) "Tint with theme" and a light chrome, which need Linux to derive chrome from a terminal theme (a light theme needs a light chrome, which DESIGN.md currently forbids); (3) the Interface switches around the toolbar and panes (toolbar layout and behaviour, pane header behaviour, padding H/V, fade, focus follows mouse); (4) Settings navigation (search, back/forward, sub-pages). The largest quality gaps are the missing inset-card grouping, inconsistent dividers and alignment, the "Change..." popups that replace Settings, and the absence of any visual preview for colour choices. Several beta items are macOS idioms (Dock and menu bar icon, Glass material, trackpad pinch, Services, traffic lights) and map to a tray option, a blurred popover surface, or nothing.

Product rules that bound parity: terminal colours stay server-owned, so "Fade content" (recolouring output) is out and "Fade surface" is allowed; split geometry is server-owned, but `session.resize_pane` takes a ratio per split, so Autobalance can be composed on the client from existing calls; attachment never creates sessions (not touched here); terminal content never animates (Animation style applies to chrome only); DESIGN.md's "no light chrome palette" is a documented decision that must be reversed before Light or Auto can ship.

- "Menu bar": Linux has no global menu bar and should not get one (single toolbar row, tiling-WM friendly; DESIGN.md). The right equivalent of Beta's View > Customize View is an "Appearance" group in Commands (Ctrl Shift P) plus the Settings rows (M01).
- Services, Writing Tools, AutoFill, Window > Move & Resize, Full Screen Tile, Stage Manager and the traffic lights are macOS-only and need no Linux counterpart; the compositor owns tiling and the app already omits minimize and maximize.

Do not build I13 variants before a tray or a themed icon has a use.

## 3. Beta UI specification

All sizes are points at 1x. Colours are samples from the dark-mode captures. Typeface is SF Pro (proportional) everywhere; only hex values in the theme editor are monospaced (about 11 pt).

### 3.1 Settings window shell (005-021)

- Window 816x850, large corner radius (about 16), soft shadow, traffic lights top left (close, minimize disabled, zoom). No title strip: the sidebar runs to the top.
- Sidebar: 214 wide, fixed (splitter disabled), fill `#0F1217`, no divider line, content fill `#0B0F13`.
  - Search field: capsule about 194x28, fill `#202328`, magnifier `#8C9298`, placeholder `Search Settings` in `#767C81`, at x+10, y 102.
  - Category outline "Settings categories", row pitch 32 (24 pt button), groups separated by about 13 pt, no dividers. Icon 20 pt rounded-square tile, label 13 pt regular `#E1EAF1`. Selected row: rounded highlight (radius 6-8, `#191D22` to `#222324`) with semibold label.
