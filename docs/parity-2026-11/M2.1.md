# M2.1 recovery: searchable, read-only Shortcuts

Initially implemented on `c24f8c4` (after PR #57), then integrated on master `00c07aa` (after 0.7.1 and PR #60), independently of the preserved Wave 2. The baseline gap report and its counts are unchanged.

## Recovered scope

- `src/app/shortcuts_page.rs` adapts the isolated `6a2b589` page, examined alongside `cc8bdad` / `parity/w2-preserved-20261111`. The later review's short opening and labelled, single-line Files rows are retained without its recorder, Settings navigation or search-shell dependencies.
- Supported registry actions are visible even unbound (`Not set`). Argument choices have distinct rows; bound aliases keep their identity. Alternate bindings share a row, with same-source, same-mode numpad twins folded into a note.
- A pinned filter accepts names, action ids, categories, key chords and sequence prefixes. Results include shadowed bindings in priority order, with sources, removed defaults and conflict notes. Escape clears the filter, then closes Settings.
- PR #57 behavior is preserved: modes compete only within their own scope; mode bindings are labelled and searchable; unsupported bound actions retain diagnostics and explanatory notes. Empty results do not promise terminal delivery, since exclusive/blocked modes can prevent it.
- Review fixes: a find-only binding no longer falsely marks the ordinary lower binding as taken or removes its Commands hint; the `Not set` status matches only the complete phrase, not fragments such as `set` or `ot`.
- Literal `+` is spelled `Plus` by the existing shared keycap formatter. Existing contrast tokens, fonts, Settings shell and keyboard section navigation are unchanged.
- README, CHANGELOG and DESIGN describe only this implemented read-only surface.

No action registrations, dispatch or remote-consent rules changed. No pane movement, session numbering, recorder, theme/font/navigation imports, fork icons, version changes, PR, merge or release work. No real/default Rex server was started.

## Verification

Using the existing parent worktree cache through `CARGO_TARGET_DIR`:

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-features
git diff --check
```

All passed: **670 tests passed, 2 existing ignored tests** (262 library, 407 app, 1 keymap fixture). Clippy succeeds; the vendored Rune dependency still emits its six existing warnings. The initial page suite had 19 tests covering registry coverage, alternates, filtering/empty results, sources/removals/conflicts, modes, aliases, unsupported diagnostics, section navigation/focus, and row geometry at 1024×700 and 640×480. The old all-bound wiring test now restores its in-memory bindings after opening Settings, so its coverage is no longer vacuous.

After integration with PR #60 and the two review fixes: **680 tests passed, 3 ignored**; fmt and clippy passed again. Exact chord queries no longer include text-prefix matches (for example `ctrl+shift+d` does not match `Ctrl Shift Down`). Unsupported-action coverage now uses move-to-new-tab because prompt navigation is implemented.
