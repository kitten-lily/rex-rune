## 1. Hosts: saved model, persistence, startup

- A host is `{label, endpoint, remote_control, collapsed, shell}` (`src/settings.rs:11-22`). `remote_control` is omitted from JSON when false (`:13`); `shell` is omitted when none (`:19`).
- Workspace file `$XDG_CONFIG_HOME/rex-linux/workspace.json` (`src/settings.rs:233-246`); written atomically through `.json.tmp` + rename (`:283-291`). `--config <path>` swaps it (`src/connection.rs:51-52`).
- Default host list on first run: one host named from `/etc/hostname` (else "Local"), endpoint = `$REX_SERVER`, else `unix://$XDG_RUNTIME_DIR/rex/server.sock`, else `unix:///run/user/1000/rex/server.sock` (`src/settings.rs:189-198`, `src/transport.rs:18-23`). `remote_control` false, `collapsed` false, no shell.
- At least one host is required, or the file is rejected (`src/settings.rs:262-265`). Every host is validated on load (`:259-261`).
- Endpoint validation (`validate_host`, `src/settings.rs:341-356`): non-empty label; `unix://` must be an absolute path; `ssh://` must parse (`ssh::Target::parse`); otherwise a URL with scheme `https|http|ws|wss` and a host. Anything else is "Use an https://, ssh:// or unix:// endpoint".
- Endpoint kinds the transport can open: `unix://path`, `https://`/`wss://` (TLS), `http://`/`ws://` (plain) (`src/transport.rs:25-37,63-79`); `ssh://` is turned into a local `unix://` forward first (`src/connection.rs:1281-1292`).
- Per-host remembered state: `last_host` (`src/settings.rs:162`), and `sessions` map endpoint to last-selected session id (`:163`, written in `src/app/workspace.rs:482-487`). Restored at launch; a CLI `--session`/`--new`/non-default `--endpoint` makes the start explicit (`src/app/workspace.rs:158-175`).
- `--endpoint` not already saved is appended as a new host, labelled by `endpoint_label` (host part of the URL/SSH target, else the path) (`src/app/workspace.rs:161-171`, `src/settings.rs:358-370`). Default `--endpoint` = `transport::local_endpoint()` (`src/connection.rs:31`).
- One worker thread plus one control connection per host, all hosts connected at once (`src/app/workspace.rs:306-348`, `src/connection.rs:683-735`). Non-active hosts get `Visibility(false)` and stop streaming terminals but stay connected (`reconcile`, `src/connection.rs:833-935`).
- `collapsed` toggles the host's group in the sidebar (`src/app/sidebar.rs:61-83`); it is the only per-host view state.
- Host icon: monitor for `unix://` endpoints, server icon otherwise (`src/app/panel.rs:455-461`).
- Default shell per host (`Host.shell`): empty = server user's login shell; one program name, no whitespace or control characters (`src/app/workspace.rs:1860-1868,1883-1889`); used by every new session, tab and split on that host (`src/layout.rs:11`, `src/app/workspace.rs:1252-1259`, `:1736`). Editable from Settings → Terminal, the host menu, and Commands.
- Edit host form fields: Host name, Endpoint, Default shell (`src/app/workspace.rs:1316-1327`). Duplicate endpoints are refused: "This endpoint is already in the workspace" (`:1873-1885`).
- Changing an endpoint is a different server: old connection dropped, new worker under a new `HostId`, saved last session forgotten, `remote_control` reset to false (`src/app/workspace.rs:391-414`, line 402 for the reset).
- Remove host: confirmation "Keep host" / "Remove host", states that sessions keep running (`src/app/dialogs.rs:197-207`); not possible for the only host (`src/app/workspace.rs:364`, `src/app/panel.rs:448-450`); inform notice "Removed X. Its sessions keep running there." (`:380-383`).
- Client label (`Settings.client_label`, default none = current hostname, "Rex Linux" if empty) (`src/settings.rs:162,224-232,377-388`). Sent as the HELLO `label`; edits apply after restart ("Visible on every host; reopen the app after editing") (`src/app/settings_view.rs:379-390`, `src/app/workspace.rs:1893-1896`).
- CLI options relevant to hosts (`src/connection.rs:29-62`): `--endpoint`, `--session <label|id>`, `--block <id>`, `--new <label>` (conflicts with `--session`), `--config`, `--window-size` (default `1440x900`), `--check-update`, plus font flags (c01). `--new` creates one session once on first connect and takes the label before the call so an uncertain reply never creates twice (`src/connection.rs:1331-1340`).

## 3. Transport, handshake and connection lifecycle

- Control socket: WebSocket path `/api/control`, subprotocol `rex.control.v1` (`src/transport.rs:200`); data sockets `/api/data`, subprotocol `rex.data.terminal.v1` (`src/wire.rs:8`, `src/connection.rs:2077`); bytes streams `rex.data.bytes.v1` (`src/upload.rs:9`). The negotiated subprotocol must echo the requested one (`src/transport.rs:87-94`).
- HELLO identity: name "Rex Linux" (discovery: "Rex Linux (discovery)"), version = crate version, platform "linux", kind `App`, label = client label, API range 10..=13, optional reconnect token (`src/transport.rs:187-244`). WELCOME revision outside 10-13 is refused with an explicit message (`:238-243`). `MIN_API_REVISION` 10, `API_REVISION` 13 (`:187-188`).
- Timeouts: whole WebSocket open 10 s (`src/transport.rs:54-61`), WELCOME 8 s (`:228-237`), ordinary request 8 s with "action was not retried" (`src/connection.rs:737-745`), `client.action` 35 s (`src/connection/actions.rs:8`), data handshake 8 s (`src/wire.rs:41-46`), keymap refresh 8 s (`src/connection/keymap.rs:34-37`).
- TCP sockets: nodelay, keepalive 15 s idle / 5 s interval / 3 retries, `TCP_USER_TIMEOUT` 30 s, so a dead peer fails within about 30 s (`src/transport.rs:33-52`). Unix sockets and SSH forwards do not get this (SSH has its own ServerAlive, section 5).
- No TLS configuration beyond rustls with the system root store (`Cargo.toml` `tokio-tungstenite` `rustls-tls-native-roots`; `src/transport.rs:64,86`): no custom CA, no pinning, no client certificates, no "accept invalid certificate" switch.
- Bootstrap: one `session.bootstrap` call with scope `"all"`, bundled data tickets for `com.superlogical.terminal`/`terminal`/`rex.data.terminal.v1`, and `attach_session_ids` only when a session is wanted, being created, or already streamed (empty list = attach none) (`src/connection.rs:554-583,1316-1328`). Bundled tickets are single-use, expiry-tracked, discarded on mismatch (`:436-510`).
- Reconnect: any control failure or SSH tunnel exit ends the attempt; status "Disconnected · reason"; retry delay `min(2^n, 8)` s with n starting at 1 (2, 4, 8, 8, …) (`src/connection.rs:1486-1493`); a manual Retry skips the wait (`:1496`). The reconnect token from the last WELCOME is reused to keep client identity; it is dropped after a failed bootstrap (`:1318-1325`). Never exits retrying.
- While disconnected: `Select` is remembered, Navigate is rejected with a notice, theme/keymap/visibility are stored, terminal search keeps working locally, everything else shows "Action not sent while disconnected. Try it again after reconnecting." and is dropped (`src/connection.rs:1497-1535`, message at `:1515`). Queued input is discarded after a failure, never replayed (`:1537-1556`).
- Data (terminal) connections reconnect independently every 1 s, first trying `rex.data` resume with offset + token, else a fresh ticket (`src/connection.rs:1955-2066`, resume at `:1979`, 1 s pause at `:2062`). Server close code 4000 ends the pane: "Terminal closed on the server".
- Detached request support (response routed to its own receiver) exists in `Transport::detach` (`src/transport.rs:98-142`); no caller outside tests was found.
- Size ownership: first sight of visible panes sends `session.own_block mode=take` when the window has focus; typing claims it; non-owners never send resize (`src/app/workspace.rs:577-600`, `src/connection.rs:1681-1712,1840-1870`).
- Background view prefetch (`session.view`, not attach) for sessions shown in a sidebar with tabs: pace 25 ms, 8 s timeout, backoff 1/5/30 s (`src/connection/prefetch.rs:14-19`).
- Events consumed (`src/connection.rs:1106-1256`): `session_created`, `session_moved` (re-list), `session_destroyed`, `session_label_changed`, `session_view_changed` (re-`session.view` when revision is higher), `block_closed`, `block_event` (clipboard copy, OSC 7501 status, process, title, notification, progress, bell), `block_owner_changed`, `keymap_changed`, `client_perform_requested`. Events at or below the bootstrap/list/view sequence are dropped (`:508-527`).

## 4. Discovery (Add host)

- Entry points: sidebar footer "Add host" (`src/app/sidebar.rs:496`), Settings → Remote Hosts "Add host…" (`src/app/settings_view.rs:484`), Commands "Add host…" (`src/app/panel.rs:628`), switcher footer (`:847`). All run `open_add_host` (`src/app/discover.rs:69-76`), a searchable list "Search your tailnet…".
- Source of machines: only `tailscale status --json` run as a local subprocess (`src/tailnet.rs:174-212`). No LAN scan, no mDNS, no QR, no server-side `hosts.list`. Errors become list text: "Tailscale isn't installed on this machine…", "Tailscale: {stderr}", "Tailscale is signed in but lists no other machines." (`:174-203`).
- Machine facts parsed (`src/tailnet.rs:7-28,110-148`): name (first MagicDNS label, else HostName, else IP), address (MagicDNS name without trailing dot, else IPv4 first then IPv6), HostName when different, OS (`linux`, `macOS`, `windows`, `iOS`, `android`), online, Tailscale SSH (any `sshHostKeys`), this-machine. This machine is listed first by the parser but hidden in the UI, as are iOS devices (`src/app/discover.rs:193-196`).
- Probe per online non-self non-iOS machine, concurrently, three endpoints in the official clients' order: `https://host`, `https://host:7297`, `http://host:7297` (`src/tailnet.rs:59-67,314-342`). First that answers (in that order) wins. Per-endpoint hello timeout 6 s; `server.status` read 2 s; close 1 s (`:288-312,271-286`). A refusal is "nothing"; other failures are "Rex check failed" with the reason (`:314-342`). Scan gives up after 20 s (`src/app/discover.rs:32`).
- The probe is a real control connection (HELLO with name "Rex Linux (discovery)") that sends only `server.status` and never attaches (`src/tailnet.rs:288-312`); the server will see a short-lived client.
- API 12 listener metadata (`listeners[]`: endpoint, transport, addresses, admission, primary) is read and described: `peer_credentials`, `anonymous`, `tailscale_owner`, `tailscale_identified`, `login_server`, unknown strings verbatim (`src/tailnet.rs:215-262`).
- List grouping: "Rex servers" (answered), "Tailnet" (online, no Rex found or check failed), "Offline"; each row names its method ("Tailscale SSH" or "SSH"), "Checking for Rex…", OS and HostName; already-saved machines are marked "Added as {label}" and stay listed so another login can be added (`src/app/discover.rs:187-276`). Footer "Enter an endpoint…" (`:272-274`).
- Selecting a Rex server: with listener facts, opens "Connect to Rex" (name + endpoint fields, note listing listeners; bound addresses are not reachability); without, adds and connects at once (`src/app/discover.rs:289-331`). Selecting any other machine opens the SSH form (below). A saved endpoint matching the answered one routes to the SSH form instead of duplicating (`:248-252`).
- Manual form "Add host by endpoint": Host name + Endpoint (`https://host.example.ts.net, ssh://user@host[/socket] or unix:///path`) (`src/app/workspace.rs:1265-1270`).
- Adding saves, activates and connects immediately; an endpoint already present is just selected (`src/app/discover.rs:430-454`).

## 5. SSH

- Endpoint grammar `ssh://[user@]host[:port][/absolute/socket]`; IPv6 in brackets; rejects whitespace, leading `-`, empty user/host, quotes/`$`/backtick/backslash in the socket path, bad ports (`src/ssh.rs:41-99`).
- Mechanism: resolve the remote socket, then `ssh -L <local.sock>:<remote.sock> … cat` with stdin piped so a dying client ends the forward; the client then attaches to the local `unix://` end (`src/ssh.rs:271-334`). Only `sshd` is needed remotely.
- Resolution when no socket is given (`src/ssh.rs:239`): first `rex server status --autostart=false` output's `unix:///…sock`, then `$XDG_RUNTIME_DIR` (default `/run/user/$(id -u)`) `/rex/server.sock`, then `~/Library/Application Support/rex/server.sock` (macOS), `/run/rex/server.sock`, `/var/run/rex/server.sock`; first that is a socket wins; otherwise "none <user>". Run as `ssh … sh -c '…'`, 30 s limit (`:443-451`). A named socket is only checked with `[ -S … ]` (`:242-246`).
- SSH options on every run (`src/ssh.rs:154-176`): `ControlMaster=no`, `ControlPath=none`, `BatchMode=yes` (never prompts), `ConnectTimeout=10`, `StrictHostKeyChecking=accept-new`, `ServerAliveInterval=15`, `ServerAliveCountMax=3`, `-p` when a port is given; the tunnel adds `-T`, `ExitForwardFailure=yes`, `StreamLocalBindUnlink=yes`. OpenSSH config, aliases, ProxyJump and agent apply; no password/passphrase/2FA prompt is possible.
- Local forward socket: `$XDG_RUNTIME_DIR/rex-linux/ssh-<pid>/<hash>.sock` (else tmp dir), directories chmod 0700, stale `ssh-<pid>` dirs of dead processes swept (`src/ssh.rs:182-232,271-295`). Forward must accept within 20 s (`:327-331`). Dropping the tunnel kills ssh and removes the socket (`:377-386`).
- Failure text is ssh's last non-generic stderr line, so Tailscale SSH banners surface; missing `ssh` binary: "ssh isn't installed on this machine" (`src/ssh.rs:411-441`). Tunnel exit is a normal disconnect and triggers reconnect (`src/connection.rs:1427`).
- A successful lookup that finds no server is a distinct `MissingServer` error with the long "No Rex server found on…" message that names the places searched and the manual `rex server install '<ssh target>'` command (preserving user/port/IPv6) (`src/ssh.rs:18-27,118-129,483-487`). Only that error sets `ssh_server_missing` (`src/connection.rs:1478-1483`; cleared at `:1362`).
- Add-over-SSH form for a listed machine: Host name, SSH user (default `$USER`), optional Rex socket; validates one user name without `@ : / ` or whitespace and an absolute socket path; note explains Tailscale SSH vs keys and what the probe found (`src/app/discover.rs:333-428`, `src/tailnet.rs:70-82`).

## 6. SSH setup: "Start personal server…"

- Offered only when: host disconnected, last failure was `MissingServer`, endpoint is `ssh://` with no explicit socket (`src/app/ssh_setup.rs:19-32`). Surfaces: host menu (`src/app/panel.rs:439-445`), Commands row (`:681`), `Intent::StartSsh` (`src/app/workspace.rs:1264`).
- Dialog (`src/app/ssh_setup.rs:204-310`, `src/app/dialogs.rs:208`): names the endpoint, previews the exact local command, states effects, buttons "Not now" (default, also Enter) and "Start personal server" (becomes "Start personal server again" after an error), "Close" while busy (closing does not cancel).
- Command run once locally: `rex --autostart=true --server <ssh endpoint> --timeout 20s api call server.status {}` (`src/ssh/setup.rs:96-139`). Uses the local `rex` from `PATH`, else `$XDG_BIN_HOME` or `~/.local/bin` (`:141-154`).
- Preflight before starting: local `rex version --json` and, over the same ssh options, remote `rex version --json`, both must report `api_revision >= 12` (`src/ssh/setup.rs:177-222`). 45 s per command (`:156,219`).
- Results (`src/ssh/setup.rs:51-94`, `src/app/ssh_setup.rs:147-201`): primary Unix listener ending `.sock` = reconnect and inform "Personal server answered… No session was created."; non-standard or TCP primary = review state with optional "Save socket endpoint" button that edits the host to `ssh://…/<socket>` (`:119-145`); failures are shown in the dialog or a sticky notice with "No automatic setup retry". If the failure happened after the start command ran, a read-only reconnect is attempted.
- No installation, service management, package install or answering installer prompts; no persistent "auto-start" setting (PRODUCT.md). Stale confirmations cannot start a different host (`src/app/ssh_setup.rs:47-78`).

## 7. Pairing / authentication

- None in the client. There is no pairing code, QR, invite link, token entry, sign-in flow or credential store in the repo (`grep` for pair/qr/login/token finds only theme "pairing" and the reconnect token). Trust comes from the transport: Unix socket peer credentials, SSH login, Tailscale identity/ACL, or whatever the HTTPS listener admits.
- No `Authorization` header or client certificate is sent (`src/transport.rs:63-96`). The README says a Rex login server "is chosen in an `https://user@host` address" (`README.md:233`), but `validate_host` accepts userinfo only incidentally and the connect path uses `url.host_str()`/port and ignores the user part (`src/transport.rs:25-37`; tungstenite 0.30 builds only a Host header). Treat that README sentence as unverified.
- Server identity shown to the user: negotiated API revision only (About, `src/app/about.rs:36-39,81-90`). `server.whoami`, `server.version` are never called.
- Reconnect identity: the WELCOME `reconnect_token` keeps the same client id across reconnects (`src/connection.rs:1293-1296`); not persisted across restarts.

## 8. Remote control (other clients driving this window)

- Wire path: server event `client_perform_requested` on the control connection; always answered by `client.reply` with the original `call_id`; never retried (`src/connection.rs:1116-1118`, `src/connection/perform.rs:82-94`). Replies carry the connection epoch and are dropped if the socket was replaced (`src/connection.rs:1713-1722`, `src/app/remote.rs:145-147`).
- Reply codes used: `refused`, `not_supported`, `bad_request`, `not_found`, `internal`; success is an explicit null result (`src/connection/perform.rs:59-80,159-196`).
- Consent: per saved host, `Host.remote_control`, **default off, even for the local socket**; reset on endpoint change (`src/settings.rs:11-14`, `src/app/workspace.rs:402`). Toggles: Settings → Remote Hosts switch (`src/app/settings_view.rs:467-477`), Commands "Turn on/off remote control for {host}" for the host on screen (`src/app/panel.rs:624,640-652`), `toggle_remote_control` (`src/app/remote.rs:24-27`). Only per-host; no per-requester, per-action or timed grants.
- The allowed set is exhaustive in `Spec::remote()` (`src/app/actions.rs:101-141`): exactly eight view-only actions: `client.tab.next`, `client.tab.previous`, `client.tab.goto` (index >= 1 or -1), `pane.focus` (left/right/up/down), `session.select` (`session_id`, optional `window_id`) as navigation; `client.sidebar.toggle`, `pane.zoom`, `pane.scroll` (integer lines) as non-navigation. Argument validation before dispatch (`:262-313`).
- Everything else of the 32 declared actions returns `not_supported` with a server-command alternative: paste/copy/send_key/new session/new tab/split/close/close tab/rename tab/rename session/settings/palette/search/switch/pane actions/zoom in-out-reset/next-previous-global/back/forward/reconnect (`:116-139`). Unknown action names also `not_supported` (`src/app/remote.rs:36-41`). The `Never`/unknown check comes before the consent check, so these never read as "off".
- Guard order after consent (`src/app/remote.rs:29-141`): bad args; a dialog or popup is open; a text field (including a mounted terminal search field) has focus; a key sequence is pending; target host not on screen (not for `session.select`); requested session not on screen; requested pane not focused; person typed within 1.5 s (navigation only, `TYPING`, `:21`); another navigation in flight; host disconnected or request older than 5 s (`MAX_WAIT`, `perform.rs:8`); no tab on screen; tab index out of range; no terminal for `pane.scroll`. Each refusal returns `refused` with "…; nothing was done."
- Expiry: pending requests not acted on within 5 s get `internal` "Rex Linux did not act in time", checked every 100 ms (`src/connection/perform.rs:135-156`, `src/connection.rs:1377,1396`). Time buffered during a busy step is counted from that step's start (`:1371-1379`).
- `session.select` is acknowledged only after the worker confirms navigation and the target is showing; 5 s deadline; unknown session/tab returns `not_found` (`src/app/remote.rs:112-120,211-300`). Can switch hosts (the requesting host becomes active); history is integrated.
- User feedback: each performed request gets one in-app notice "{host}: {requester} performed {action}" (non-sticky, 6 s) (`src/app/remote.rs:302-324`, `src/app/workspace.rs:853-857`); the first refused request per host per launch while consent is off shows "{requester} on {host} asked for {action}. Remote control is off (Settings → Remote Hosts)." (`:162-178`). Other refusals are silent in the UI; they are logged through `log::info!` (`:303-309`), which has no logger installed (section 12). Nothing raises the window or sends a desktop notification.
- Requester display: name from `info.name` (control and bidi characters stripped, 40 chars) plus principal display/login/kind (`src/connection/perform.rs:31-50`). Displayed only; not a permission filter.
- The client also declares its 32 actions to the server through `client.keymap` (`actions::declarations`, `src/app/actions.rs:508-530`; `src/app/workspace.rs:624-635`), including "Not available remotely. …" descriptions, so `rex actions` shows them regardless of consent (README).
- Local actions returned by the server's own `client.action` (queued shortcuts) are separate from Remote control; known names run once on the UI thread, guarded by host/session/keymap generation and skipped with an info notice otherwise (`src/app/workspace.rs:504-531`). Unknown names ignored.
- `client_call_requested` (cross-server relay) is never produced because no `servers` list is sent; not handled (`docs/plans/roadmap-0.5.2.md` section 7, issue #20).

## 9. Notifications and program activity

Settings → Notifications (`src/app/settings_view.rs:212-272`; defaults `src/settings.rs:44-68`; all persisted under `notifications` in workspace.json):

| Setting | Default | What it does |
| --- | --- | --- |
| `show_in_tabs` (Activity in tabs) | on | Words on tabs ("Needs approval", "Question", "Needs sign-in", "Needs input", "Error", "Done", "Bell", "Paused n%") and the pane header word |
| `system_notifications` (Desktop notifications) | on | Master switch; also gates program messages; sub-switches disabled when off |
| `blocked` (Needs you) | on | Notify when a background tab's program becomes Blocked |
| `error` (Fails) | on | Notify on Error |
| `done` (Finishes) | on | Notify on Working/Blocked -> Done/Idle |
| `working` (Starts working) | **off** | Notify when it starts working |
| `program_messages` (Messages from programs) | on | Forward OSC 9 / OSC 777 notifications |

- Activity source: OSC 7501 status records from the terminal creator (`program_status_changed`/`program_status_removed` events, `program_status` method); fields `state` (idle/done/working/error/blocked; unknown reads as idle), `kind` (permission/question/auth), `effective_app`/`app`, `title`, `msg`, `progress` 0-100 (`src/connection/activity.rs:10-104`). Fold per tab: Blocked > Error > Working > Done > Idle (`src/app/activity.rs:86-139`).
- Other block events: `process_changed` (foreground program and ancestors), `title_changed`, `desktop_notification`, `progress_report` (OSC 9;4: set/indeterminate/pause/error/remove), `bell` (`activity.rs:148-194`). Queries on first sight of a block: `program_status`, `title`, `process` (`src/connection.rs:950-1003`). Reset on reconnect (`:1303-1312`).
- Program icons on tabs by foreground/reporting program: claude/claude-code, codex, opencode, pi/omp, nvim/vim/vi, git/lazygit/tig, cargo/rustc/rustup, ssh/mosh, else terminal (`src/app/activity.rs:142-155`).
- Tab word rules: trouble always; then unseen bell; then paused/failed OSC 9;4; then "Done" until the tab is seen (`:161-179`). Progress bar 2 pt under the pill (`:184-215`). "Seen" = window focused, host active, session and tab on screen (`:233-242`).
- When a notification fires (`:246-296,298-342`): only for live changes (not state restored by queries), only if the tab is not seen, only if the state's switch is on. Summary `"{program} · {word}"` (or `"{tab} · {word}"`), body = message + `"{session} · {host}"`. Idle never notifies. Program notices (`DesktopNotice`) skip tabs that are seen and use the program's title/body, else tab name (`:344-393`); at most 32 queued per host, 32 bells (`src/connection.rs:300-337`).

Click raises the window using the `ActivationToken` signal (Wayland focus) and selects host, session, tab (`:90-104`, `src/app/activity.rs:427-437`). The last 64 notifications remember their targets (`notify.rs:12,79-84`).
- Headless tests collect notes in an outbox instead of D-Bus (`src/app/activity.rs:415-424`).
- In-app notices (toasts): `notify` = sticky error, `inform` = information gone after 6 s, at most three kept, identical text deduplicated (`src/app/workspace.rs:758-764,836-857`); corner Top right (default) or Bottom right (`NoticePosition`, `src/settings.rs:24-30`, Settings → Interface → Notices). Per-host connection notice from the worker (`HostModel.notice`) and per-pane worker notices (`Model.notice`) are lifted into toasts (`src/app/mod.rs:162-170`).
- Clipboard from terminal programs (OSC 52 `clipboard_written`, `selection_copied`): up to 8 MiB, accepted only from the focused pane of the selected session while the window is focused and no panel is open; reads from the desktop clipboard by programs are refused by design (`src/connection/clipboard.rs:1-106`).
- Window-level feedback: window title only; no tray icon, badge, taskbar attention request, sound or do-not-disturb.

## 11. Updates and install channels

- Check is metadata only: fetch `latest.json` and `latest.json.minisig` from `https://github.com/shuv1337/rex-rune/releases/latest/download/` (`src/update.rs:17-22`); HTTPS only (loopback `http` only for the probe flag), 64 KiB manifest / 4 KiB signature caps, 10 s timeout, 5 redirects, user agent `rex-linux` (`:27-31,992-1039`). Never downloads binaries; no self-update.
- Verification: Minisign (Ed25519 over BLAKE2b-512 prehash) against two embedded keys, CI `packaging/keys/release.pub` and offline backup `release-backup.pub`; key id must match; the trusted comment must be `rex-linux vX.Y.Z latest.json` and equal the manifest version (`:24-25,176-229`). Manifest schema 1, product `rex-linux`, strict `X.Y.Z` versions, tag `vX.Y.Z`, notes URL pinned to the repo's release tag, targets only `x86_64-linux-gnu`/`aarch64-linux-gnu`, tarball URLs under the tag, SHA-256 hex, `.deb` names (`:63-166`).
- State `$XDG_STATE_HOME/rex-linux/update.json` (default `~/.local/state`): `last_checked`, `latest_version`, `highest_verified`, `announced_version`, `dismissed_version`, `notes_url`, `published`, `unsupported_floor`; advisory file lock (`:740-760,878-935,1041-1060`). Anti-rollback: a manifest below `highest_verified` is refused (`:937-990`). `update_from` greater than the running version yields "unsupported floor" (manual upgrade required) (`:960-990`).
- Schedule: first check 30 s after launch (`STARTUP_DELAY`), then at most every 24 h while running; failed checks back off a full 24 h; background failures are silent (`src/update.rs:27-28`, `src/app/updates.rs:91-118,372-420,470-492`). Settings: `updates.check` default on (`src/settings.rs:72-82`); `REX_LINUX_NO_UPDATE_CHECK=1|true|yes` turns checks and the toast off and disables the switch (`src/update.rs:864-868`).
- Install channel detection (`src/update.rs:421-526,627-725`): build channel `source` or unset = Source (no automatic checks), `nix` = Nix; otherwise a `share/rex-linux/channel` marker beside the binary (`channel=pacman|deb|nix|other`, optional `hint=`) or a verified `~/.local/share/rex-linux/install.json` receipt (path + SHA-256 of the binary) = Tarball (install.sh), else Unmanaged. Omarchy detected from `/etc/os-release` `ID`/`ID_LIKE` (`:683-702`).
- Channel guidance (`src/update.rs:529-625`): Pacman (`omarchy update` or `sudo pacman -Syu rex-linux-bin`, custom hint honoured), Tarball (verified `install.sh` curl command), Deb (`sudo apt install ./rex-linux_<v>_<arch>.deb`), Nix (`nix flake update rex-rune` / `nix profile upgrade rex-linux`), other package (hint), Source (git pull + cargo build), Unmanaged (download from Releases, no command).
- UI: toast with accent dot, summary, dismiss X ("Dismiss for this version"), "What's new" (opens release notes with `xdg-open`) and "Updates…" (`src/app/updates.rs:268-367`); shown when a verified newer version exists, not dismissed, and checks are enabled. Settings → Updates (`:134-266`): Installed version + channel label, Automatic update checks switch (disabled for Source or env opt-out), Release status with "Check now" (forced, ignores the 24 h gate, resurfaces a dismissed notice, shows "up to date" notice or sticky "Update check failed"), Available update row with What's new and Dismiss, Upgrade command with Copy command.
- Commands: "Update Rex Linux (x.y.z)…" when available (`src/app/panel.rs:673`), "Check for updates" (`:627`). About links: repository, release notes, MIT license (`src/app/about.rs:92-121`).
- CLI: `rex-linux --check-update` forces a check, prints one line with channel guidance and exits 0 (up to date), 10 (available or unsupported floor), 1 (error) (`src/main.rs:5-9`, `src/update.rs:1082-1126`). `rex-update-probe` adds `--current-version`, `--manifest-url`, `--signature-url`, `--public-key-file`, `--state-path`, `--allow-loopback-http` (`src/bin/update_probe.rs`).
- Rex server updates: nothing. The client never reads `server.version`, never compares server and client revisions beyond the 10-13 range and never suggests upgrading a server (an API revision below 11 only blocks uploads: "this host's Rex server is too old to receive files", `src/connection.rs:1578-1581`).

## Absent or partial

- **No pairing or credential flow** (section 7). No QR, code, invite, token, passkey, login-server sign-in, password or passphrase prompt. SSH is `BatchMode=yes`, so a host needing a password or an unlocked key cannot connect and shows only the ssh error line.
- **`https://user@host` is not a documented-in-code auth path**; the README sentence about it is not backed by client code (section 7).
- **No TLS customization:** no custom CA, certificate pinning, client cert, or "trust this certificate" prompt; an untrusted certificate is simply "Rex check failed" or a disconnect.
- **Discovery is Tailscale-CLI only:** no LAN/mDNS, no QR, no listing from the server's `hosts.list`; no discovery without the `tailscale` binary. The probe tries only 443/7297 and never uses listener addresses to redirect (by design). iOS devices and this machine are hidden.
- **No management of the Rex server:** no start/stop/restart, `server.config_reload`, built-in Tailscale enable/login/rename, version display or update hint. The only server-start path is the one-shot SSH "Start personal server…" through the local `rex` CLI; no remote install, no service management.
- **No host organisation beyond collapse:** no host reordering (only sessions have Move up/down), grouping, colours, import/export, sync of saved hosts from a server, or per-host settings other than label, endpoint, shell, remote-control, collapsed.
- **Remote control is coarse:** one switch per host; no per-action or per-requester rules, no time-limited grant, no history view; only the first off-state refusal and performed actions are visible; `log::info!` records go nowhere. Eight view-only actions only: no typing, creation, closing, clipboard, dialogs, interface zoom, or cross-host preference changes. Requesters are not authenticated by the client.
- **No cross-server relay** (`client_call_requested`): no `servers` list is sent. Documented as not implemented (#20).
- **Cannot drive other clients:** `client.perform`, `client.list`/`client.inspect`, `session.list_clients` and the `client_*` events are unused, so no "who is connected" view and no remote-driving of Mac/iOS clients from here.
- **Notifications are minimal:** freedesktop only; no urgency, sound, per-host/per-session/per-program mute, quiet hours, grouping, replacing or auto-closing when the tab is seen, no tray/badge; notifications for a tab are suppressed only when that tab is in front of a focused window. A failed `Notify` call (`?` at `src/app/notify.rs:70-76`) or a missing D-Bus service ends the notifier thread for the rest of the session, with one stderr line. Working notifications are off by default. State restored by queries after reconnect never notifies. No push/mobile.
- **Agent integrations are local only:** no setup of agents on SSH/remote hosts, only Claude Code/Codex/OpenCode/Pi/OMP (plus whatever `rex skill status` lists); depends on a local `rex` binary (README says attachment itself does not).
- **Updates are advisory:** notice and copyable command only; no download, verify-and-install, rollback, beta/prerelease channel (`StableVersion` rejects prerelease tags), release-notes rendering (opens browser), or Rex server update checks. Source builds never auto-check (manual Check now works). Flatpak/RPM/AUR channels are not detected (`OtherPackage` only via marker).
- **File download absent:** `download_begin` (API 13) is SDK-only; the roadmap plans a "Download file…" dialog but nothing is implemented (`docs/plans/roadmap-0.5.2.md`).
- **Diagnostics are thin:** no log output (no logger), no log viewer, no connection/latency/throughput view, `ProtocolStats` not displayed, no export beyond Copy version info, no crash reporting. `Transport::detach` is unused outside tests.
- **No floating layers, tab reordering, block move/swap/detach UI** (server methods unused); splits are only created via `session.new_split` and resized via `session.resize_pane`.
- **Platform scope:** Linux only (freedesktop notifications, `xdg-open`, `/proc`, XDG dirs). Wayland pointer behaviour and multi-seat are unvalidated (README Current scope). API revisions 10/11 are not tested live.

## Constraints (product rules that bound parity)

From AGENTS.md, PRODUCT.md and DESIGN.md:

- **Attachment-only.** Attaching/reconnecting never starts, stops or reconfigures a server, and never creates or destroys a session; creation is always an explicit user action. The one exception is the separately previewed, one-time "Start personal server…" (default "Not now"), which never enables future auto-starts and never installs packages or services (AGENTS.md "Conventions"; PRODUCT.md "Principles", "SSH attachment"; DESIGN.md "Interaction").
- **Server owns the terminal.** Content, colours and split geometry come from the server; the client may only declare a terminal theme (`set_theme`) under the ownership rules; it never recolours output or invents layout. No client-owned columns or free-form pane geometry (fork-harvest skip of scrolling layouts; `docs/fork-harvest-2026-11.md`).
- **Remote availability is default-deny and exhaustive** in `Spec::remote()`; consent belongs to the saved host, never the requester; replies stay on their connection epoch; the allowed-set test stays pinned (AGENTS.md). Requests never raise the window or open a dialog, and every performed request is named in an in-app notice (PRODUCT.md, DESIGN.md).
- **Failed input is never replayed;** a transport failure pauses affected panes rather than queueing input (AGENTS.md, DESIGN.md).
- **Keys:** workspace shortcuts consume their keys but every binding is removable/replaceable; ordinary keys flow through `client.key`; only explicit `pane.send_key` uses `block.event` to bypass Lua bindings (AGENTS.md).
- **Supported API window is 10-13;** older servers are refused rather than carried along while Rex is in alpha (PRODUCT.md). Uploads require 11, SSH setup requires 12.
- **Quiet when healthy.** No status dots, "Connected" labels, terminal size readouts, keyboard-hint footers; words only for trouble ("Offline", "Reconnecting", "input paused") in `WARNING` next to the fixing action (DESIGN.md "Do and don't"). Notices are toasts: errors sticky, info about 6 s, at most three (DESIGN.md "Interaction").
- **Chrome motion yes, terminal motion no.** Popups, sidebar and highlights animate with the springs in `theme.rs`; terminal content never animates (cursor blink requests draw steadily) (AGENTS.md, DESIGN.md).
- **Compact, one-row chrome.** One 52 pt toolbar, tabs are Rex windows, server windows are called "tabs"; no minimize/maximize buttons; popovers never open popovers; dialogs for forms and confirmations; destructive confirmations name the target and default to "Keep running"/"Keep host"/"Not now" (DESIGN.md "Layout and shape", "Interaction").
- **Dark chrome only,** token palettes in `src/app/theme.rs` are the source of truth; no light chrome (DESIGN.md "Colour"). Hard-coded colours in views are disallowed.
- **Safe by default:** closing a pane or tab names what ends and defaults to Keep running; closing the app leaves server programs running (PRODUCT.md).
- **Honest README:** do not document features that are not implemented or checked (AGENTS.md); parity claims should likewise cite checked behaviour. Vendored Rune/rexrs/ghostty-vt carry only minimal documented patches; rexrs types are regenerated with `python3 codegen/generate.py`, never hand-edited (AGENTS.md "Vendored patches").
- **Updates never self-install:** official and Nix builds verify signed metadata and show channel-specific guidance; background failures are silent; there is no binary download (PRODUCT.md "Capabilities", DESIGN.md "Interaction").
- **Native Rune look:** take Rune defaults on bumps; do not restore old pixels (project memory note `native-rune-look`).
- **Linux scope:** Wayland and X11 desktop only; Kitty animated graphics, AT-SPI accessibility and distribution packages beyond tarball/deb/Arch/Nix are out of scope for now (PRODUCT.md "Out of scope").
