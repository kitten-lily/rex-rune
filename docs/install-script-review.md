# Installer supply-chain review — 2026-11-10 (PST)

Requested independent review: **Pi, `anthropic/claude-opus-5-5`**, shared checkout,
read-only. Scope: verification before execution, key handling, pipe-to-shell,
downgrade protection, uninstall scope and release integration.

The reviewer found no verification bypass and no release-blocking objection,
conditional on the remaining container matrix and the changes below. It checked
the BLAKE2b/Ed25519 format and the global trusted-comment signature, embedded
keys and explicit tag-only fallback, four-package checksum contract and ten-asset
publication. Its own release-tool run passed all 17 tests; ShellCheck was clean.

## Applied findings

- Both verifiers now reject legacy unprehashed `Ed` signatures; the same `ED`
  format and public-key record checks precede either route. Regression fixture
  signs with `minisign -S -l` and requires both to refuse.
- The final invocation is a complete shell command group, not a bare function
  name. Truncation through every byte of the last call is tested both as a file
  and through shell stdin, preserving `--uninstall`/`--version` arguments.
- All seven CI container images are digest-pinned. Installer-test and attestation
  checkouts disable persisted credentials; containers receive only a read-only
  checkout, never the signing environment. Package mirrors and GitHub remain
  external availability dependencies, as for the existing build jobs.
- Added the installer changelog entry and removed the duplicate Unreleased heading.
- Key IDs now print in minisign's conventional uppercase byte order, matching
  the README; SHA-256 fingerprints remain over the complete public-key record.
- Uninstall runs before distro/package-install guards and removes only the five
  documented user files plus the receipt, preserving preferences. Tests preserve
  unrelated files and a system-package sentinel. Shared desktop/icon caches may
  be regenerated by their owning tools; directories are not recursively removed.
- `--force` can repair a binary unable to report a stable version. It does not
  bypass downgrade protection for a recognized version or any cryptographic check.
- Signing verification requires the installer to equal the reviewed source bytes,
  including for offline signing, not merely carry a valid signature.
- Version syntax rejects embedded newlines; `/etc/os-release` is sourced in a
  subshell so it cannot overwrite installer variables.
- The integration test refuses to run outside Docker. Unknown tag keys that do
  not match the signer are now an explicit negative case.

No additional review delegation was used for these small fixes. The implementation
agent checked them with the regression tests. Release-specific results and URLs
are recorded in `docs/0.5.2-verification.md` after publication.

## Deliberate bounds

The five-minute download timeout and 256 MiB tarball cap remain; failures install
nothing. Private staging and owner-only desktop files are intentional for a user
install. The receipt is not created until U3; a future receipt currently uses
`path` and `sha256` fields and requires Python 3 only when validating that file.
The unsigned initial script delivery is explicitly documented as trust on first
use; a retained/reviewed copy or an independently verified script avoids relying
on a freshly downloaded script's own trust roots.
